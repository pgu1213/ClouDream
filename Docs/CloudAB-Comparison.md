# ClouDream A/B 구름 비교

2026-10-15. Unity 6000.6.2f1 / HDRP 17.7 / Windows D3D12. 이번 변경은 커밋하지 않는다.

## 직접 비교하기

Unity 메뉴 **ClouDream → Lost Skies → Comparison → Create Or Open A-B Scene**을 실행한다. 비교 씬은 `Assets/LostSkiesClouds/Scenes/CloudABComparison.unity`다. Play하면 A/B 선택 패널이 열린다.

에디터는 비교 씬의 Edit 상태로 두었다. 독립 실행은 `Builds/CloudAB-Release/ClouDreamHybrid.exe`를 연다. 기본 씬의 연결을 바꾸지 않고 같은 F6/Tab/F7을 사용할 수 있다.

- **F6**: 비교 패널 열기/닫기. 닫으면 기존 자유 비행 입력을 사용한다.
- **Tab**: 현재 카메라 위치에서 A/B 전체 경로를 전환한다.
- **F7** 또는 **Capture same-pose A / B pair**: 카메라·날씨·시간·바람 위상을 고정하고 A/B를 각각 촬영한다. A의 준비가 끝나면 좌우 비교를 표시한다. 최대 대기 시간은 60초이며, 시간이 초과되면 남은 임시 표면을 포함한 현재 A를 촬영한다.
- **Close comparison**: 촬영 전에 선택한 경로와 시간/입력 상태로 돌아간다.
- 촬영 파일은 `Screenshots/CloudAB/날짜-A.png`, `날짜-B.png`에 저장한다. PNG는 디스플레이 RGB와 불투명 알파로 저장하고 비교 텍스처는 sRGB로 표시한다.
- **F8**: 기존 기준 렌더러의 상세 설정. 이 설정은 B의 로브 품질을 바꾸지 않는다.

F6 패널에서 Cloud OFF / Surface / Surface + local volume / Full / Reference를 선택할 수 있다. `Actual`은 현재 사용된 경로이며, A의 `cell proxies`는 전체 reference 복귀 횟수가 아니라 임시 표면으로 표시 중인 셀 수다. B는 셀별 GPU 점유 readback을 사용하지 않으므로 B의 종류별 셀 수는 보수적 표시 후보 수다.

## A: 기존 하이브리드 + 예측 준비

기존 Concept V2의 밀도·운해·상층·띠와 marching tetrahedra 경로를 유지했다. 한 셀이 준비되지 않았다는 이유로 화면 전체를 기존 레이마처로 돌리는 조건을 제거했다.

- 빈 셀은 같은 절대 셀의 저가 3D 표면으로 즉시 표시한다. 상층은 기존 몸체·어깨·로브 배치를 공유하고 운해는 공통 높이장을 사용한다. 화면 방향에 고정한 빌보드가 아니다.
- 임시 표면에서는 48표본 밀도 적분을 실행하지 않는다. 준비된 셀만 정상 볼륨 경로를 사용한다.
- 상주와 품질을 나눠 16 격자를 먼저 준비하고, 필요한 셀을 32→64로 올린다. 이전 LOD는 새 자료가 준비될 때까지 유지한다. 빈 것으로 확인된 셀은 고해상도로 반복 생성하지 않는다.
- 기본 생성 예산은 3개 작업 / 프레임당 12슬랩이다. 위치 변화, 카메라 방향, 회전 속도로 뒤 4km / 옆 6km / 앞 12~16km의 준비 영역을 만든다. 속도×예측 지연도 더하며 순간이동은 속도로 오인하지 않는다.
- GPU가 간접 그리기 인수를 완성하면 다음 그리기에 쓴다. AsyncGPUReadback은 점유·오버플로 계측용이며 표시 가능 여부의 필수 대기가 아니다.
- GPU 오버플로도 해당 셀의 임시 표면으로 처리한다. 정상/임시 표면의 간접 인수를 GPU가 별도로 기록한다. 원점 이동은 키나 절대 형태를 바꾸지 않는다.

## B: 스타일 로브 표면 + 국소 볼륨

B의 상층은 여덟 타원체의 매끈한 결합으로 새로 설계했다. 위치·시드는 기존 프로필을 공유하되 원래 밀도장의 복제본으로 표현하지 않는다. `CloudAB-Lobes.asset`의 폭·높이·결합·어깨·작은 변위·실루엣 폭을 조절할 수 있다. 스칼라는 정확한 SDF가 아니므로 구 추적 도약에 사용하지 않는다.

- 상층에는 셀별 3D 필드와 marching tetrahedra 버퍼를 보관하지 않는다. 로브 파라미터에서 표면 정점을 직접 만들고 같은 해석적 형태에 투영한다.
- 운해는 기존 연속 높이장을 유지한다. 17×17 높이/법선/변위 마스크 버퍼만 절대 셀별로 보관하고, 바람·날씨 변위는 현재 프레임에 적용한다.
- 중·원거리 표면은 거의 불투명하며 하나의 깊이 버퍼가 픽셀별 앞뒤를 결정한다. 셀 중심 거리 정렬을 사용하지 않는다. 실루엣의 좁은 띠에만 디더를 적용한다.
- 가까운 후보만 16×16 화면 타일에 나열하고, 볼륨은 한 번의 화면 패스에서 전방 적분한다. 중첩 밀도는 같은 위치의 최대값으로 결합해 같은 구름을 여러 번 감쇠하지 않는다.
- 가까운 상층의 여덟 로브 파라미터를 GPU에서 프레임당 한 번 준비한다. 밀도 표본마다 셀 난수와 부모 배치를 반복하지 않는다. 직접 계산과 준비된 계산의 GPU 최대 밀도 차이는 약 0.000019다.
- 국소 적분은 실제 로브의 회전된 경계와 광선의 교차 구간으로 제한한다. 조밀한 내부에서는 실제 출구까지 허용하고, 먼 운해 표면은 픽셀 거리로 유지한다.
- 전체 표면과 먼 표면을 분리해 국소 볼륨을 먼 구름·불투명 장면 깊이까지 합성한다. 광원·팔레트·공기 원근·노출·최종 업샘플링은 기존 계약을 재사용한다.
- 내부 안개는 같은 로브/운해 밀도에서 나온다. 별도 HDRP Local Fog를 중첩하지 않는다.

Player 측정 도구는 같은 입력으로 Off / A Surface / A Surface+Volume(생성 정지) / A Full / B Surface / B Full / Reference의 7개 단계를 실행한다. 반복마다 정순·역순으로 순서를 교차한다. A의 고정 단계는 먼저 전체 경로로 준비한 뒤 생성만 멈춘다. 이동 중 새 셀은 임시 표면으로 나타날 수 있으므로 고정 단계의 결과를 완전히 같은 메시 작업량의 뺄셈으로 해석하지 않는다.

```text
-cloudABBenchmark -cloudQuit -cloudOutput <directory> -cloudRepeats 3
```

측정이 끝난 폴더는 `Tools/CloudAB/Summarize.ps1 -Directory <directory>`로 합산한다. 원본 JSON을 보존하고 `Summary.json`에 모드별 P95/P99/최대·누락·하위 마커·자원을 기록한다.

기본은 12초 실제 시간 비행이며 각 구간에는 카메라 이동·컷·운해 하강이 있다. 기존 36초 측정과 직접 합산하지 않는다. `-cloudStationary`는 카메라·시간·날씨를 고정해 비행 중 HDRP 변화 비용과 분리하는 진단이다. `-cloudFixed`는 고정 포즈 표본 방식이다.

Development는 구름 전체와 생성·표면·볼륨·합성 GPU 마커를, Release는 최종 전체 프레임을 판정한다. FrameTiming의 CPU main/render/present wait와 GPU 시간을 함께 기록한다. 이들은 지연 스트림이며 포즈별 동기 측정이 아니다. GPU 표본 누락을 0ms로 채우지 않는다.

고정 환경에서는 B가 A보다 빠르고 두 경로 모두 전체 P95 목표 안에 든다. 그러나 요구한 비행·환경 변화 코스는 미달이므로 이를 최종 성능 합격으로 대체하지 않는다. OFF의 전체 GPU 평균도 비행 9.427ms에서 고정 1.273ms로 달라져, 약 10ms를 HDRP의 고정 비용으로 단정할 수 없다.

현재 시간대 공급자는 시각이 바뀔 때 HDRP `PhysicallyBasedSky`의 색·노출과 태양/달을 갱신하며 하늘 모드는 `OnChanged`다. 다음 비용 분석 후보는 **카메라만 이동 / 시각만 변화 / 날씨만 변화**를 분리한 GPU 프로파일이다. 이번 진단은 세 조건을 함께 고정했으므로 차이 전부가 하늘 재생성 때문이라는 인과관계까지 입증하지 않는다. 하늘 갱신 간격이나 조명 품질을 이번 A/B 작업에서 임의로 낮추지 않았다.

## 채택 범위와 남은 점

원본 기본 씬과 기본 빌드 씬은 전환하지 않았다. 비교 씬과 독립 Player에서 사용자가 두 표현을 판단한다. 기본 추가 자원 예산 128MiB, 전체 P95 6.944ms, 구름 평균 2ms·P95 3ms 목표를 그대로 유지한다.

A의 임시 표면/LOD 교체는 형태 차이가 보일 수 있고 셀 간 반투명 합성 순서도 기존 방식이다. B는 정확한 볼륨의 재현보다 둥근 덩어리와 큰 명암 면을 택한 실험이다. 로브 접합부·디더·저밀도 경계와 빠른 회전은 시각 검토 대상이다. 자동 유한값 통과가 레퍼런스 스타일 승인이나 모든 팝 제거를 뜻하지 않는다.

이번 비교에는 외부 패키지, 임포스터 베이크, URP 전환, full voxel 압축 기술을 추가하지 않았다. 가장 먼 구름의 임포스터/지평선 셸은 A/B 판단 이후 별도 후보로 남긴다.
