# ClouDream 하이브리드 구름 구현과 검증

작성일: 2026-10-15. 대상은 Unity 6000.6.2f1 / HDRP 17.7 / Windows D3D12다.

## 채택 상태

운해 높이장 메시, 상층·띠구름 GPU 메시, 같은 형태를 사용하는 근거리 적분과 내부 안개를 독립 경로로 구현했다. 기존 `LostSkiesCloudSea`와 기본 빌드 씬은 유지한다. `CloudHybridValidation`은 비교·검증용 씬이며, 기본 경로 채택은 시각 검토와 Player 성능 판정 후 결정한다.

성능 목표는 RTX 4080 / FHD에서 전체 프레임 P95 ≤ 6.944ms, 구름 GPU 평균 ≤ 2ms·P95 ≤ 3ms다. 생성과 합성 비용도 포함한다. GPU 표본이 없는 결과를 구름 예산 통과로 취급하지 않는다.

## 구조와 실제 변경 범위

- `CloudFormationProfile.TryGetHybridGeometry()`가 보정된 형태 입력을 제공한다. 운해·상층·Concept V2 스타일이 지원하며 다른 형태와 추출값 전용 모드는 기존 경로를 사용한다.
- 기존 Concept V2의 큰 몸체·로브·운해·띠구름 생성 함수, 셀 난수, 팔레트 응답을 공통 HLSL로 이동했다. [함수 본문 보존 검사](Validation/Hybrid/Shared-Geometry-Extraction.json)는 이동 전후 본문이 동일한지 확인한다. 새로운 밀도 샘플링·두 표본 차폐·메시 조명은 새 근사 구현이다.
- `CloudHybridPass`가 기존 패스 앞에서 실행된다. 같은 카메라의 하이브리드 출력이 준비된 경우에만 기존 패스 실행을 한 번 생략한다. 준비 중·미지원·오류 상태는 기존 출력으로 복귀하고 실제 적용 상태를 표시한다.
- `CloudEnvironmentSource`, 날씨 컨트롤러, 시간대·팔레트·태양/달, 보존 노이즈와 `CloudWorldOrigin`은 재사용한다. 별도 HDRP Local Fog나 시간 재투영은 추가하지 않았다.

## 형태·GPU 데이터 계약

형태와 배치는 절대 구름 좌표로 생성한다. 원점 이동은 카메라와 그리기 좌표만 바꾸며 셀·시드·불변 형태의 키는 유지한다. 날씨·바람·입사광은 현재 프레임에서 평가한다.

| 자료 | 계약 |
|---|---|
| 셀 키 | C# `(x, z, kind)`, GPU `(kind, x, z, grid)` |
| 종류 | 0 운해, 1 상층, 2 띠구름 |
| 불변 3D 필드 | RGBAHalf: 미터 스칼라, 대표 크기, 변위 마스크, 기본 밀도 배수 |
| 격자 | 16/32/64개 구간, 축마다 `grid + 1`개 표본 |
| GPU 삼각형 | 72바이트, 위치 3개와 큰 형태 법선 3개 |
| 원자 카운터 | 생성 삼각형 수와 오버플로 플래그 |
| 간접 그리기 | vertex count / instance count / start vertex / start instance |
| 선형 출력 | RGB는 누적 방사량 L, alpha는 투과율 T |
| 깊이 | 표면의 광선 거리와 재구성용 불투명 장면 깊이를 별도 보존 |

미터 스칼라는 정확한 SDF가 아니다. 등가면의 선형 보간과 밀도 평가에만 사용하고 구 추적 도약 거리로 사용하지 않는다. Half 범위를 넘지 않도록 저장 스칼라를 제한한다.

상층과 띠구름은 marching tetrahedra로 만든다. 띠구름의 수직 격자는 공유 GPU 난수로 계산한 실제 고도 주변 2km에 대응시켜 먼 LOD에서도 얇은 층을 샘플링한다. 운해는 공유 몸체의 상단 교차로 만든 높이장과 하부 면을 사용한다. 경계는 공통 16분할 앵커와 동일한 바람 변위를 사용한다.

## 스트리밍·전환·수명

- 표시 범위 바깥 8km까지 카메라 주변을 미리 준비하고 실제 프러스텀에 필요한 메시만 그린다. 기본 논리 셀 상한은 384개다. 가까운 셀부터 생성하며 빈 셀은 점유 결과만 남기고 GPU 버퍼를 해제한다.
- 기본 생성량은 프레임당 Z 슬랩 4개, 동시 작업 1개다. GPU 카운터를 비동기로 확인한 후 교체하고 오버플로 결과를 화면에 채택하지 않는다.
- 불변 형태가 바뀔 때만 캐시를 무효화한다. 날씨·조명·바람 변경은 메시 재생성을 요구하지 않는다.
- 기본 거리 LOD는 6km / 24km, 표시 범위는 기존 적분과 같은 42km다. 메모리 배분은 먼 셀부터 격자를 낮추며 교체 여유를 남긴다.
- 초기 추가 자원 예산은 128MiB다. 보고되는 바이트는 소유 필드·버퍼·카메라 타깃의 명시적 저장량이다. 보존 노이즈, 기존 비교 렌더러, HDRP 자체와 드라이버 할당 오버헤드를 포함한 전체 VRAM 수치는 아니다.
- 같은 구름의 메시와 볼륨은 L/T를 보간한 뒤 한 번 합성한다. 큰 형태의 표면 경계 기준 1km 이내는 볼륨, 1–2km는 전환 구간이다. 주 적분 기본값은 48표본, 광원 조회는 2표본이다.
- 메시 투영과 적분 광선은 HDRP의 같은 비지터 투영 행렬을 사용한다. 셀 합성은 보수적 화면 경계로 제한한다. 근평면을 가로지르면 전체 화면으로 처리한다.
- 내부 여부는 AABB 진입점이 아닌 실제 카메라 밀도로 판정한다. 적분은 구름 출구나 불투명 장면 깊이까지 진행하며, 조밀한 잔여 에너지는 동일한 입사광으로 닫는다.
- 카메라별 출력은 최대 두 개를 보존한다. resize·퇴출·OFF·종료에서 소유 자원을 해제한다. 전경 재구성은 장면 깊이를 비교하는 4표본 업샘플링이다.

## 사용 및 재검증

Unity 메뉴 `ClouDream → Lost Skies → Hybrid → Create Or Open Validation Scene`을 실행하고 Play한다. 기존 F8 설정창의 Hybrid 선택으로 기존 경로와 비교한다. 준비 중에는 기존 구름이 표시되므로 상태의 실제 적용 여부를 함께 확인해야 한다. 하단의 기존 최적화 제어는 비교용 볼류메트릭에 적용된다.

Unity MCP 호출 연결점:

```csharp
ClouDream.LostSkies.Editor.CloudHybridTools.CreateValidationScene();

// Play에서 실제 GPU 출력·시각 캡처·환경·수명을 검사한다.
ClouDream.LostSkies.Editor.CloudHybridValidation.Begin();

// Edit에서 명시적 씬을 빌드한다. 에디터 GUI 지연 콜이 멈췄다면 RunQueuedBuild를 호출한다.
ClouDream.LostSkies.Editor.CloudHybridTools.QueueDevelopment();
ClouDream.LostSkies.Editor.CloudHybridTools.RunQueuedBuild();
```

Development/Release 빌드는 전용 비교 실행 파일이다. 기존 참조 경로의 키워드는 compact + 거리별 밀도/조명 조합으로 제한하며, 이 실행 파일에서 다른 실험 조합을 선택하는 것은 지원하지 않는다. 일반 프로젝트 빌드의 변형 정책은 바꾸지 않는다. 빌드 대상·D3D12·FHD·FrameTiming 설정은 빌드 동안만 적용하고 복구한다.

Player 인자는 `-cloudHybridBenchmark -cloudQuit -cloudOutput <directory>`다. 기본은 36초 실제 비행이고 `-cloudFixed`를 추가하면 동일한 360개 포즈를 사용한다. R/H/H/R/R/H 순서로 각 경로를 3회 측정한다. 자동 워밍업은 필요한 캐시와 지연 GPU 스트림을 측정에서 분리하고, 측정 중 생성과 기존 경로 복귀는 결과에서 제외하지 않는다. `Cloud.ComparisonTotal`은 같은 프레임의 하이브리드 생성·렌더와 기존 경로 복귀를 합산한다. 초기 `Development-Flight-Initial` 자료는 복귀 비용이 빠진 이전 마커로 측정한 중간 결과이므로 최종 구름 예산 판정에 사용하지 않는다.

Play 검사는 2026-10-15 01:44 UTC 실행에서 통과했다. 운해 위·아래·내부, 상층 내부, 낮·석양·밤, 원점 이동의 8개 출력이 유한했고, 운해 검사 최대 투과율은 0.008 이하였다. 조명 변경 투과율 차이, 원점 이동 출력 차이, 날씨 복귀 출력 차이는 각각 0이었다. 날씨 중단 연속성·메시 재생성 없음, 두 카메라 분리·resize 해제, 전경 가림·OFF 자원 회수도 통과했다. 메시가 빈 하늘로 판정한 영역에 근거리 적분이 잘못된 불투명 면을 만드는 회귀 검사의 비율은 0이었다.

초기 시각 검토에서 발견한 운해 타일 틈, 적분 광선 Y 반전, 운해 아래에서 다른 타일의 상부 뒷면이 보이는 문제를 수정했다. 현재 정지 캡처는 큰 형태·연속성 확인 자료이며 고속 비행·LOD 팝의 최종 합격 자료는 아니다.

Player 측정은 Development/Release 각각 R/H/H/R/R/H 6회, 총 12회가 정상 종료됐다. [전체 결과와 원시 보고서](Validation/Hybrid/Performance-Summary.md)를 보존했다. 두 빌드는 같은 런타임 소스 SHA-256과 검증 씬 해시를 사용한다.

| 지표 | 기존 | 하이브리드 | 판정 |
|---|---:|---:|---|
| Release 전체 프레임 평균 | 19.593ms | 11.621ms | 평균 40.7% 감소 |
| Release 전체 프레임 P95 | 30.081ms | 18.809ms | 목표 6.944ms 미달 |
| Development 구름 GPU 평균 | 9.334ms | 1.356ms | 평균 목표 2ms 이내 |
| Development 구름 GPU P95 | 19.544ms | 8.691ms | 목표 3ms 미달 |
| 비행 중 추가 소유 GPU 자원 최대 | — | 84.17MiB | 128MiB 이내 |

Release 하이브리드 9,295프레임 중 965프레임(10.38%)이 셀 준비 때문에 기존 경로로 복귀했다. 복귀 당시 최대 미준비 가시 셀은 4개였다. 하이브리드가 실제 적용된 프레임만 따로 봐도 wall 평균 10.845ms·P95 12.801ms이므로 스트리밍만 해결하면 144FPS가 된다고 단정할 수 없다. 전체 HDRP·CPU 잔여 비용의 원인은 별도 프로파일링 대상이다.

Development 구름 GPU 스트림은 생성·합성·기존 경로 복귀를 포함한다. GPU 표본은 지연되어 프레임/포즈와 일대일 대응하지 않으며, 배출 구간 때문에 프레임 수보다 9개 많은 9,272개가 수집됐다. Release 구름 GPU 마커는 없으므로 미검증으로 남기고 Development 값으로만 GPU 예산을 판정했다. **현재 버전은 전체 프레임과 구름 P95 기준에 미달해 기본 채택하지 않는다.**

## 현재 구현의 한계

원래 볼륨의 픽셀 단위 복제가 아니다. 큰 형태와 팔레트는 공유하지만 유한 격자, 높이장 상단 추출, 두 표본 차폐와 조밀한 내부 근사로 명암·표면이 달라진다. 서로 다른 몸체는 보수적 셀 중심의 순서로 합성하므로 복잡한 교차에서 정확한 픽셀별 순서를 보장하지 않는다. LOD 교체와 고속 비행의 최악 시각은 별도 검토 대상이다.

원본 생성기의 보존 GPU 노이즈를 재사용한다. 새 메시·필드·적분 코드를 Lost Skies의 원본 HLSL이나 디컴파일 보강 자료의 원본 소스로 표현하지 않는다.

## 계획 대비 상태

| 항목 | 현재 상태 |
|---|---|
| 공통 형태·환경 계약, 절대 셀 캐시 | 구현 및 기존 생성 계약 검사 통과 |
| 운해 상·하부 메시, 상층·띠 GPU 등가면 | 구현 및 세 종류 점유·유한값 검사 통과 |
| 근거리 적분·동일 밀도 내부·L/T 보간·장면 깊이 | 구현 및 진입/내부/하부 정지 시점 검사 통과 |
| 설정 UI·실제 상태·명시적 씬/빌드·GPU 마커 | 구현 및 Development/Release 빌드 성공 |
| 날씨 중단·복귀·원점·두 카메라·resize·OFF | Play 검사 통과 |
| 교차하는 다른 구름의 정확한 픽셀별 깊이 순서 | 미충족: 현재 셀 중심 거리 정렬 |
| 모든 LOD 경계·고속 비행의 팝 없음 | 미입증: 셀 준비 중 기준 경로 복귀가 발생 |
| 성능 목표와 기본 씬 전환 | 목표 미달, 기본 전환 보류 |

이는 기본 채택이 끝난 렌더러가 아니라, 실패 조건과 재측정 도구가 포함된 독립 구현이다. 표시 범위 전체의 3D 형태를 처음부터 매 프레임 적분하던 비용은 줄였으나, 남은 깊이 순서·스트리밍·전체 프레임 비용을 해결한 뒤 다시 채택 판정해야 한다.
