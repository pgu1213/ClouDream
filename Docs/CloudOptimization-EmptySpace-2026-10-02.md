# 빈 공간 건너뛰기 개선과 벤치마크 결과

상층 구름의 빈 공간 판정을 더 좁고 정확한 교차 범위로 바꿨다. **밀도 조회량은 줄었지만, 현재 장면의 전체 FPS는 개선되지 않았다. 기본 OFF를 유지한다.** RTX 4080에서 같은 이동 벤치마크를 7,200프레임 측정한 결과 평균 FPS는 33.78에서 32.14로 낮아졌고, 구름 GPU 시간은 28.03에서 29.55ms로 늘었다. GTX 1660의 FHD 60FPS 목표를 달성한 결과가 아니다.

## 이번에 적용한 범위

사용자가 요청한 네 번째 기능과 해당 기능의 측정·프로파일링만 다뤘다. 구름 생성식, 운해의 연속성, 날씨 공급 계약, 기존 거리별 품질 및 시간 재투영의 동작은 유지했다. FluidNinja 자료의 보수적인 지원 범위 제한 원리를 현재 Unity 절차식 구름에 맞게 구체화한 새 구현이며, Unreal 코드나 수작업 복원본을 원본 소스로 이식한 것이 아니다.

- 기존 상층 AABB 교차를 실제 밀도 경계인 회전 타원체 교차로 바꿨다. 접선 근처 부동소수점 오차를 위해 반경 2m와 거리 양끝 1m의 여유를 둔다.
- 기존 표본 거리, 진입 이분 탐색, 1024회 반복 상한을 그대로 유지한다. 얇은 구름을 건너뛰는 큰 거리 점프는 도입하지 않았다.
- 추가 점유율 볼륨이나 GPU RT를 만들지 않는다. OFF에서는 기존처럼 해당 셰이더 경로를 제외한다.
- F8의 기존 `Skip empty cloud regions`가 개선된 판정을 사용한다. F9에는 이 옵션만 OFF/ON/ON/OFF로 비교하는 버튼을 추가했다.
- 효과가 반복 변동 또는 2% 측정 여유 이하면 벤치마크가 `INCONCLUSIVE`로 표시한다. 10% 초과 반복 변동 및 GPU 표본 누락도 구분한다. 이 기준은 통계적 신뢰구간을 대신하지 않는다.

구현 위치: [교차 판정](D:/Dev/ClouDream/Assets/LostSkiesClouds/Runtime/CloudRayIntervals.hlsl), [자동 비교](D:/Dev/ClouDream/Assets/LostSkiesClouds/Runtime/CloudBenchmark.cs), [GPU 정확성 검사](D:/Dev/ClouDream/Assets/LostSkiesClouds/Editor/CloudEmptySpaceValidation.cs).

## 최종 이동 벤치마크

Unity 6000.6.2f1, HDRP, D3D12, RTX 4080, Editor Play. Game 뷰 1920×1080, 구름 75%인 1440×816. 정오 12시·바람 0, 게임 시간 고정, VSync 및 FPS 제한 해제. 셀 캐시·지원 범위 검사·압축 버퍼·깊이 업샘플링 ON. 이번 기능만 비교하기 위해 시간 재투영·거리별 품질·공간 조명·팔레트 전용 경로·그림자 종료는 OFF다.

기존 CloudRoute-v1의 상층 회전·관통·운해 경로를 각 600프레임씩 실행했다. 각 조건마다 전체 경로 1,800프레임 워밍업 후 1,800프레임을 측정했다. 네 조건의 카메라 경로, 정지된 게임 시간, 해상도, 프로필, 셰이더 의존성 해시가 같다. 각 조건에서 GPU 마커와 FrameTiming 표본 1,800개를 확보했다.

| 조건 | 평균 FPS | 최저 FPS | 1% low FPS | 프레임 p95 ms | 구름 GPU 평균 ms |
|---|---:|---:|---:|---:|---:|
| OFF 1 | 33.16 | 19.69 | 21.26 | 40.58 | 28.58 |
| ON 1 | 32.26 | 17.98 | 20.04 | 42.54 | 29.44 |
| ON 2 | 32.01 | 19.00 | 20.44 | 43.13 | 29.67 |
| OFF 2 | 34.41 | 20.74 | 22.14 | 39.34 | 27.48 |

총 프레임/총 시간으로 합산한 FPS는 **33.78 → 32.14, 4.85% 감소**다. 구름 GPU 평균은 **28.03 → 29.55ms, 5.43% 증가**다. OFF 반복 변동은 3.91%, ON은 0.75%다. ON 두 번 모두 OFF 두 번보다 느렸으므로 현재 경로에서 활성화할 성능 근거가 없다. 이 수치를 다른 GPU의 예상 성능으로 환산하지 않는다.

## 어느 부분에서 비용이 늘었는가

같은 경로 구간의 실제 프레임 간격을 OFF 두 번/ON 두 번씩 합산했다. 아래는 GPU 타이머를 카메라 자세와 대응시킨 표가 아니라 프레임 구간의 평균이다. 지연되는 GPU 마커는 개별 자세와 직접 대응시키지 않는다.

| 경로 | OFF 프레임 평균 ms | ON 프레임 평균 ms | 해석 |
|---|---:|---:|---|
| 상층 회전 | 29.16 | 28.91 | 약 0.9% 감소, 반복 변동보다 작아 확실한 개선으로 보지 않음 |
| 관통 | 29.52 | 30.59 | 약 3.6% 증가 |
| 운해 | 30.13 | 33.85 | 약 12.3% 증가, 전체 결과의 주요 손실 구간 |

전체 Raymarch 평균은 OFF 약 27.98ms, ON 약 29.50ms다. 깊이 복사는 약 0.008ms, 합성은 약 0.037~0.047ms였다. 따라서 이번 손실은 업샘플링이나 합성보다 Raymarch 내부에서 발생했다. GPU 사용률은 거의 100%, GPU 클록 평균은 약 2738~2739MHz였다. CPU 프로세스 사용률은 논리 코어 정규화 기준 약 1.63~1.88%다. CPU 메인 스레드 시간에는 대기가 포함되어 있으므로 이를 별도의 순수 CPU 계산 비용으로 해석하지 않는다.

작업량도 별도 셰이더로 직접 계수했다. 같은 경로의 18개 자세, 320×184, 총 1,059,840개 광선이다. 이 계수 검사는 장면 깊이를 넣지 않았으며 GPU 타이밍 측정과 분리했다. 카운터가 실행 비용을 바꾸므로 계수 셰이더의 시간을 성능 수치로 사용하지 않는다.

| 항목 | 옵션 OFF | 기존 AABB 방식 | 개선된 타원체 방식 |
|---|---:|---:|---:|
| 주 루프 반복 | 474,350,621 | 474,350,621 | 474,350,621 |
| 주 밀도 조회 | 474,350,621 | 248,119,572 | 240,266,015 |
| 생략한 빈 표본 | 0 | 226,231,049 | 234,084,606 |
| 교차 구간 조회 | 0 | 250,559,271 | 242,640,245 |

주 밀도 조회는 기존 방식보다 **3.17%**, OFF보다 **49.35%** 감소했다. 이 수에는 시작점, 이분 탐색, 법선, 그림자의 밀도 조회가 포함되지 않는다. 픽셀마다 `반복 = 밀도 조회 + 생략 표본`의 보존 검사를 통과했다.

개선 방식은 상층 회전 구간에서 주 밀도 조회의 약 81.1%, 관통에서 약 62.0%를 생략했다. 하지만 운해에서는 **1.33%만 생략하면서 약 1.55억 회의 교차 구간 조회**가 추가된다. 기존 밀도 함수도 빈 위치에서는 지원 범위 검사로 빠르게 반환하므로 생략한 호출 전체가 고비용 연산인 것은 아니다. 그림자·법선·채워진 구름의 적분 비용도 남는다.

이를 종합하면 **운해에서 얻는 생략 효과보다 구간 판정·분기·상태 유지 비용이 큰 것**으로 해석한다. GPU 명령별 시간, 레지스터 spill, wave occupancy는 측정하지 않았으므로 구체적인 하드웨어 원인까지 확정하지 않는다. [계수 원본](D:/Dev/ClouDream/Benchmarks/EmptySpace-WorkCounts.json), [계수 도구](D:/Dev/ClouDream/Assets/LostSkiesClouds/Editor/CloudEmptySpaceWorkProfile.cs).

활성 구름 RT는 모든 조건에서 18,800,640바이트, 약 17.93MiB로 같았고 할당 횟수는 1로 유지됐다. Editor 프로세스 RAM과 어댑터 전체 VRAM은 다른 작업을 포함하는 별도 값이며, JSON에 기록되어 있다. 이번 기능의 추가 RT 비용은 없다.

## 비교 후 제외한 변경

빈 표본을 별도 내부 루프에서 처리하는 방식과, 상층·띠구름의 고도 구간을 광선마다 추가로 보관하는 방식도 분리 측정했다. 기존·교차 범위만·루프만·조합·OFF를 정순/역순으로 각 540프레임 측정했다. 조합은 약 28.42~28.46ms, OFF는 약 27.72~27.85ms로 활성화 이득이 없었다. 기존 방식은 36.27~29.78ms로 크게 흔들려 단일 개선율의 기준으로 사용하지 않는다.

추가 루프와 고도 상태의 이득을 확정하지 못했으므로 최종 구현에는 타원체 교차만 남겼다. 이는 최종안이 모든 시험 변형 중 가장 빠르다는 뜻이 아니다. [분리 측정 목록](D:/Dev/ClouDream/Benchmarks/skip-profile-20261002-130331.txt), [정순·역순 실행 도구](D:/Dev/ClouDream/Assets/LostSkiesClouds/Editor/CloudShaderBenchmark.cs)에 기록을 남겼다.

초기 짧은 비교 및 오후 조명에서의 별도 비교는 최종 수치에 합산하지 않았다. 같은 묶음 안의 시간은 고정됐지만 묶음 사이에는 자동 시간 진행으로 조명이 달랐다. 최종 비교는 정오를 명시적으로 고정했다. 시험 소스는 `Benchmarks/EmptySpaceSources`와 `Benchmarks/EmptySpaceAblationSources`에 보관했고, 임시 셰이더 에셋은 Unity MCP로 제거했다.

## 정확성 검증과 사용법

- 12개 극단 조건 및 이동 경로 18개 자세 × 4개 비교, 총 120개 GPU 비교 통과. 변경 전 셰이더 대비 OFF, OFF 대비 ON, 기존 방식 대비 개선, 거리별 품질과 조합을 검사했다. RGB·투과율·가중 깊이 최대 차이는 모두 0이었다.
- 음수 셀, 축과 평행한 광선, 최대 변위, 원점 이동, 운해 내부, 상층 비활성, 낮은 태양, 혼합 조명, 밝은 HDR 림을 포함했다. 검증 표본 밖의 모든 가능한 설정에 대한 수학적 증명은 아니다.
- 시간 재투영에서 옵션 전환에 따른 이력 초기화 4회 통과. [정확성 원본](D:/Dev/ClouDream/Benchmarks/EmptySpace-Validation.json).
- 비교 취소 시 셰이더·옵션·카메라·카메라 지정·비행 입력·시간 배율·백그라운드 실행·CPU/GPU 프로파일러 설정 복원을 확인했다. F9 창에서는 비행 입력이 중단된다.
- Unity MCP로 컴파일 및 Play 검증을 수행했다. 최종 Console 오류·경고 없음.

Play에서 **F8 → Skip empty cloud regions (tighter bounds)**로 선택한다. 현재 장면은 기본 OFF 사용을 권장한다. **F9 → Compare empty-space skipping: OFF / ON / ON / OFF**를 누르면 현재 나머지 설정을 유지한 자동 비교를 실행한다. `Long / 600`이 이번 최종 측정 길이다. 완료·취소 시 원래 옵션으로 돌아온다.

[F9 설정창](D:/Dev/ClouDream/Screenshots/Optimization/EmptySpace-F9-FHD.png). 원시 벤치마크와 스크린샷은 기존 프로젝트 규칙에 따라 Git 제외 디렉터리에 로컬 보관한다. 기본 장면 설정은 유지했으며, 목표 GTX 1660 실측과 Player 빌드 측정은 이번 결과에 포함되지 않는다.
