# 공간 조명 캐시 구현과 검증 결과

**2026년 10월 2일 측정 정정:** 후속 재구성 검사에서 `CloudSceneFramePerformance`가 side와 inside의 경로를 옵션마다 다시 계산해 위치·방향을 바꾸던 문제를 발견했다. 아래 최초 측정 표의 해당 두 행과 내부 42.6% 개선 주장은 같은 시점의 A/B로 사용할 수 없다. home은 고정 시점이었다. 수치 정확성·자원·Play 검사는 별도 도구이며 이 오류와 구분한다. 측정 도구는 고정 home에서 경로를 한 번만 계산하도록 수정했다. 후속 결과는 [재구성 보고서](D:/Dev/ClouDream/Docs/CloudOptimization-Reconstruction-2026-10-02.md)에 기록한다. 공간 조명 기본 OFF는 유지한다.

2026년 10월 2일, 승인받은 픽셀 간 조명 공유 실험을 Unity HDRP에 구현했다. **공간 조명은 기본 OFF, 선택 간격은 16m**다. 고정 home 시점에서는 느려졌고, 정밀 설정도 모든 명암 오차 기준을 통과하지 못했다. 내부 후보 시점의 성능 개선 주장은 위 측정 오류로 철회한다. F8에 실험 옵션과 16·32·64m 선택을 제공한다. GTX 1660, FHD, 60 FPS 달성은 확인하지 못했다.

## 요구와 참고 원리

사용자는 기존 구름 최적화와 Play 설정창을 우선하고 유체 반응을 후속으로 분리했다. 이번 승인 범위는 여러 픽셀이 조명 계산을 공유하는 캐시의 구현 및 성능·명암 오차 비교다. 원래 밀도장, 연속 운해, 상층 분포와 환경 공급 계약을 유지했다.

[FluidNinja 자료 검토](D:/Dev/ClouDream/Docs/FluidNinja-Optimization-Review-2026-10-01.md)에 기록했듯, 공간 lighting cache는 Unreal Heterogeneous Volume 렌더러의 원리다. FluidNinja SVOL의 자체 공통 캐시 소스로 확인한 것은 아니다. 이번 C#·HLSL은 Unity의 현재 절차식 구름에 맞춘 신규 구현이며, 수작업 복원 자료를 원본 구현으로 취급하지 않았다.

## 구현

- 64³ 격자 세 개를 하나의 64×64×192 RGFloat 3D 텍스처에 저장한다. 추가 메모리는 **6 MiB**다. R은 태양 방향 7회 조회의 적분 밀도, G는 위쪽 3회 조회의 적분 밀도다.
- 간격은 선택값의 1·2·4배다. 16m 선택은 16/32/64m 격자를 사용한다. 각 레벨은 카메라로부터 축별 최대 거리 16~22셀에서 다음 레벨 또는 기존 계산으로 부드럽게 전환한다. 최외곽 반경은 각각 약 1.4/2.8/5.6km이며 구 형태가 아닌 축 정렬 범위다.
- 격자는 밀도 좌표의 월드 격자에 고정한다. 텍스처 창을 8셀 단위로 옮기되, 레벨 혼합은 연속 카메라 거리로 계산하여 창 이동과 혼합 경계가 함께 튀지 않게 했다.
- 매 카메라 렌더마다 현재 태양·날씨·바람으로 재계산한다. 범위 밖의 구름이 만드는 그림자도 원래 밀도 함수를 사용해 포함한다. 과거 프레임 조명은 재사용하지 않는다.
- 법선, 시선 방향, 팔레트, rim, 기존 광선별 60m 보간은 각 광선에서 계산한다. 광선의 밀도·투과율·깊이를 캐시로 대체하지 않는다.
- `CloudFormationProfile.SupportsSpatialLightCache`가 지원을 선언한 Concept V2에서만 사용한다. 미지원 형태와 실험용 운해 높이장 동시 요청은 기존 조명으로 복귀한다. `CloudEnvironmentSource`는 그대로 사용한다.
- 간격 변경은 RT를 재할당하지 않는다. OFF에서는 3D RT를 반환하고, 다시 ON일 때 할당한다. 셰이더 keyword로 OFF 경로에서 공간 조회를 제거한다.

초기 4배 간격 확대안은 광범위한 명암 오차 때문에 채택하지 않았다. 최종안은 범위를 줄여 품질을 우선하지만, 그만큼 원경에서 계산 공유의 이점이 작다. 원경 성능 저하의 세부 GPU 원인까지 확정한 것은 아니다.

## 실제 Game 카메라 GPU 측정

Unity 6000.6.2f1, HDRP 17.7, D3D12, RTX 4080 Editor Play에서 측정했다. Game 뷰 1920×1080, 구름 75%인 1440×816, 정오, 바람 0, 1차 최적화 ON, 빈 구간 제한·그림자 종료 OFF다. 검사 중 Volume을 Game 카메라로 한정하고 종료 후 복원했다. 각 경우에 워밍업 20개와 유효 표본 48개를 수집했다.

다음은 최초 **Cloud.Total GPU p50 / p95(ms)** 기록이다. **side와 inside 행은 시점이 달라 A/B 비교가 무효**이며 기록 보존을 위해 남긴다. 깊이 복사, 셀 및 조명 캐시 생성, Raymarch, 합성을 포함하며 전체 HDRP 프레임은 아니다.

| 시점 | 공간 OFF | 16m | 32m | 64m |
|---|---:|---:|---:|---:|
| home | 37.26 / 57.11 | 55.09 / 63.85 | 60.38 / 68.46 | 50.27 / 56.72 |
| side | 49.40 / 59.02 | 61.92 / 70.06 | 63.46 / 73.35 | 48.96 / 56.45 |
| inside candidate | 9.59 / 10.48 | 5.51 / 6.20 | 5.46 / 6.22 | 5.47 / 6.03 |

같은 시점인 home은 증가했다. side·inside의 증감률은 판단에 사용하지 않는다. 캐시 생성 자체의 p50은 0.10~0.26ms이며 위 합계에 이미 들어 있다. 별도 순차 측정 간 Editor 시간 변동도 있으므로 과거 보고서의 절대값과 누적 개선율로 연결하지 않는다.

FrameTimingManager의 전체 GPU 시간은 구름 패스보다 짧게 반환되어 모든 조건에서 일관성 검사를 실패했다. 이 값을 전체 GPU 시간이나 목표 장비 FPS로 사용하지 않는다. 설정창의 Whole frame은 `Time.unscaledDeltaTime` 평균이며 Editor·VSync 등이 포함된다.

## 명암 오차와 안정성

320×184 독립 GPU 출력에서 15조건×3간격, 총 45개 비교를 실행했다. home, 수평선, 상공, 운해 내부, 음수 셀, 축 평행, 최대 변위, 원점 오프셋, 상층 OFF, 낮은 태양, 혼합 조명, 강한 HDR rim, 밤, 측면, 내부 후보를 포함한다. 모든 비교에서 **투과율과 가중 깊이 차이는 0**이었다.

실험의 색 오차 예산은 최대 채널 오차 0.03, 전체 픽셀 평균 0.002, 구름 픽셀 p95 0.01이다. 이는 이번 실험의 판정 기준이며 사용자가 승인한 시각 품질 허용치라는 뜻은 아니다. 수치는 노출·톤매핑 전 선형 HDR 값이다.

| 기본 간격 | 색 기준 통과 | 전체 조건 중 최대 RGB 오차 | 가장 큰 평균 오차 | 가장 큰 구름 픽셀 p95 |
|---|---:|---:|---:|---:|
| 16m | 13 / 15 | 0.06250 | 0.001724 | 0.013672 |
| 32m | 10 / 15 | 54.32422 | 0.018498 | 0.084473 |
| 64m | 5 / 15 | 54.33203 | 0.102552 | 0.467529 |

16m의 실패는 운해 내부와 강한 HDR rim 조건이다. 운해 내부는 최대 0.03760, 평균 0.001724, p95 0.013672였다. 강한 rim은 최대 0.06250이고 평균은 약 0.000002였다. 32/64m의 큰 최대값은 의도적으로 광원을 강하게 한 HDR rim 조건에서 나왔다. 따라서 넓은 격자를 일반 권장값으로 삼지 않았다.

격자 노드 4,096개의 직접 차폐 비교 최대 오차는 0.000122였고, 밀도 비교 최대 오차는 0이었다. 검사에 실제 구름이 포함되는지도 확인했다. 원점 이동, 환경 값을 바꾼 뒤 원상 복구, 매 렌더 갱신, 동일 RT 재사용, OFF 자원 해제, 미지원 형태 복귀가 통과했다.

32m 격자의 스냅 경계 255.99→256.01m 이동에서 고정점의 최대 적분 밀도 변화는 0.02393으로 기준 0.1 이하였다. 256m 전체 이동에서는 레벨 선택 변화 때문에 최대 217.52의 차이가 남는다. 이는 RGB 수치가 아니다. 스냅 불연속 검사 통과가 장거리 비행 중 명암 변화가 전혀 없다는 증명은 아니며, 장시간 이동 영상 평가는 남아 있다.

기존 Concept V2 연속 운해·상층 분포·GPU 안정성 검사와 날씨 전환 중단·재전환 검사가 통과했다. 형상 검사는 상층 표본 65,536개와 경계 표본 20,800개를 포함한다.

## Play 사용과 재검사

Play에서 **F8 → Share cloud lighting across pixels (experimental)**을 켜고, 먼저 **16 m / Fine**으로 같은 시점에서 OFF와 비교한다. 32m와 64m는 적용 범위가 넓어지면서 명암 오차가 커질 수 있다. 원경에서 느려지면 OFF를 유지한다. 변경은 현재 Play 실행에만 적용한다. Restore session defaults는 시작 설정을, Optimizations OFF / compare는 공간 조명을 포함한 모든 선택적 최적화 OFF를 적용한다.

Unity 메뉴 **ClouDream → Lost Skies → Optimization**에서 Validate Spatial Lighting과 Measure FHD Spatial Lighting을 실행할 수 있다. 후자는 FHD Game 뷰와 Play가 필요하다. 원시 JSON은 `Screenshots`에 저장되며 Git에서 제외될 수 있다. Play 설정 검사는 `CloudOptimizationPlayValidation.Start()`로 실행한다.

실제 Play의 16회 설정 전환, F8 열기·Esc 닫기, 비행 입력 중단·복구, 간격 변경 중 재할당 없음, OFF 메모리 반환, 시작 설정 복원이 통과했다. Unity Console 오류·경고는 없었다. [Play 검사 기록](D:/Dev/ClouDream/Screenshots/Optimization-PlayValidation.json), [FHD 설정창](D:/Dev/ClouDream/Screenshots/Optimization/Spatial-F8-FHD.png).

동일 home·정오의 1280×720 장면 캡처도 확인했다. [OFF](D:/Dev/ClouDream/Screenshots/ConceptV2/Spatial-OFF/pose-00-hour-12.png), [16m](D:/Dev/ClouDream/Screenshots/ConceptV2/Spatial-Fine16/pose-00-hour-12.png), [64m](D:/Dev/ClouDream/Screenshots/ConceptV2/Spatial-Wide64/pose-00-hour-12.png). 64m는 근처 운해 명암 변화가 보이며, 정지 캡처의 HDRP 이력 차이를 엄격한 GPU 버퍼 오차와 혼동하지 않는다.

목표 GPU의 Player 측정, 장시간 비행·급회전 시각 검토, 근사 오차에 대한 사용자의 수용 판단이 남아 있다. 전체 화면의 60 FPS를 달성하려면 추가 계산 구조 개선이 필요하지만, 깊이 인식 재구성이나 시간 재투영을 이번 승인에 자동으로 포함하지 않았다.
