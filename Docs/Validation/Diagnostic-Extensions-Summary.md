# Normal Cache / Far Surface 실제 비행 진단

2026-10-05 · Development Player / RTX 4080 / Unity 6000.6.2f1 / Direct3D12

**관측된 법선 함수 호출의 3.13%가 캐시로 완전히 대체됐고, Far Surface는 최초 진입 시도의 5.73%에서 승인됐다.** 반면 법선 필드는 기록 프레임 사이마다 세 cascade를, Far Surface는 매번 한 번씩 생성했다. 이 문서는 작업량 진단이며 속도 개선을 판정하지 않는다. 원자 계수와 동기 GPU readback이 켜진 실행의 GPU 시간·FPS는 대표 성능 결과에서 제외한다.

전체 설정, 원자료 SHA-256, 분모를 포함한 비율, 20슬롯 표면 계수와 구간별 집계는 [Diagnostic-Extensions-Summary.json](Diagnostic-Extensions-Summary.json)에 저장했다.

## 실행 조건과 계측 범위

두 확장 기능을 각각 독립적으로 켠 1회 비교다. 출력은 1920×1080, 구름 버퍼는 **960×544**다. 구간당 12초인 3구간의 실제 시간 경로를 사용했으며 이동 720m/s, 첫 구간 회전 45도/s, 낮밤 주기 1,200초, 바람·날씨 중단/역전 입력이 적용됐다. 보존 원본 GPU 노이즈를 사용한다.

공통 설정은 구름 해상도 50%, 거리별 밀도·조명 간격 1.5배, 셀 캐시·지원 범위 검사·압축 출력 ON이다. 상층/운해 형태 필드, 공간 차폐 캐시, 빈 공간 도약, 적응 적분, 시간 재투영·타일 압축은 OFF다. `normal-cache`는 법선 캐시만, `surface-hybrid`는 Far Surface만 켰다. 서로 다른 관측 시각·프레임 수이므로 각 행을 동일 자세의 짝으로 비교하지 않는다.

| 프리셋 | 기록 프레임 | 진단 스냅샷 | 마지막 스냅샷 경로 시각 | 스냅샷의 구름 픽셀 합계 |
|---|---:|---:|---:|---:|
| normal-cache | 1,100 | 74 | 35.818140s | 38,645,760 |
| surface-hybrid | 1,038 | 70 | 35.886062s | 36,556,800 |

진단은 15프레임마다 **직전 완료 렌더**의 카운터를 읽는다. 각 카운터는 렌더마다 초기화되므로 아래 합계는 관측 스냅샷의 합이며 **전체 비행의 모든 프레임·모든 광선 합계가 아니다.** 15배 또는 64배로 확장하지 않았다. 워밍업이 별도로 있어 첫 행의 누계가 0일 필요는 없다.

정상 완료·오류 없음, 슬롯 길이(법선 4/표면 20/기존 캐시 12/시간 13), 15프레임 관측 간격을 확인했다. 모든 스냅샷에서 법선·캐시의 `query=full+blend+exact`, 표면 생성의 결과 합계, `최초 진입 시도=승인+거부`, `fallback=거부 사유 합계`가 일치했다. Far Surface 생성 광선 수도 매 스냅샷에서 proxy 480×272=130,560과 일치했다.

## Normal Cache: 호출 대부분이 원래 계산으로 복귀

법선은 `((x×1973+y×9277)&63)==0`인 **1/64 화면 픽셀에서 발생한 함수 호출**을 기록한다. 한 광선에 여러 법선 요청이 있을 수 있으며 생성 커널은 이 호출 집계에 포함되지 않는다. full은 정확 법선 재평가 없이 캐시를 사용한 경로, blend는 캐시와 정확 법선을 함께 계산한 경로, exact는 원래 법선으로 복귀한 경로다. full을 화면 품질 통과율로 해석하지 않는다.

| normal-cache 관측 호출 | 횟수 | query 366,405회 대비 |
|---|---:|---:|
| query | 366,405 | 100% |
| full | 11,481 | **3.1334%** |
| blend | 2,461 | 0.6717% |
| exact | 352,463 | **96.1949%** |

설정은 첫 셀 크기 256m, 근거리 정확 평가 2,500m, 8개 코너 방향 일치 기준 0.995다. 현재 4슬롯 계수로는 exact의 원인을 근거리·범위 밖·유효값·방향 불일치로 세분할 수 없다. 따라서 낮은 full 비율을 한 원인에만 귀속하지 않는다.

| 관측 구간 | 스냅샷 | 법선 query | full / query |
|---|---:|---:|---:|
| 0–12s | 25 | 131,196 | 1.6936% |
| 12–24s | 28 | 91,952 | 1.4312% |
| 24–36s | 21 | 143,257 | 5.5446% |

구간은 readback 호출의 경로 시각으로 나눴다. 직전 GPU 렌더를 특정 자세·날씨 이벤트와 정확히 동기화한 표는 아니다.

## Far Surface: 생성 성공과 최종 승인을 구분

표면 카운터는 1/64 마스크를 사용하지 않고 **관측 렌더의 모든 build/consumer 호출**을 기록한다. 생성은 화면 축마다 절반인 480×272 proxy에서 수행되며, 주 광선의 최초 진입에서 후보를 검사한다. 한 번도 검사에 진입하지 않은 출력 픽셀은 최초 진입 시도의 분모에 포함되지 않는다. 기본 근거리 제외 거리는 12,000m다.

|---|---:|---:|
| 불투명 표면 생성 | 2,203,698 | 24.1126% |
| 근거리 또는 내부 | 4,197,055 | 45.9237% |
| 얇거나 분리된 구간 | 299,081 | 3.2725% |
| 불투명 미도달 또는 탐색 소진 | 2,439,366 | 26.6912% |
| 비유효 값 | 0 | 0% |

| 최초 진입의 후보 검사 결과 | 횟수 | 최초 진입 20,847,317회 대비 |
|---|---:|---:|
| 표면 승인 | 1,194,474 | **5.7296%** |

| 장면 깊이 제한 | 34 | 0.000163% |

볼륨 fallback은 **19,652,843회(최초 진입 대비 94.2704%)**다. 표면 승인 1,194,474픽셀을 관측 스냅샷 전체 구름 픽셀 36,556,800으로 나누면 **3.2674%**다. 이 비율은 표본 렌더의 전체 화면 분모이며, 앞의 5.7296% 및 proxy 생성 성공 24.1126%와 의미가 다르다. 승인은 실제 표면 경로 사용을 뜻하며 색 오차 통과를 뜻하지 않는다. 표면 화질·수치 계약 결과는 [Redesign-FarSurface-Summary.md](Redesign-FarSurface-Summary.md)에 별도로 기록돼 있다.

거부 사유는 코드의 첫 반환 조건이다. 동일 후보에 잠재적으로 겹치는 모든 실패 원인의 독립 빈도가 아니며, 0으로 관측된 항목도 스냅샷 사이 모든 프레임에서 발생하지 않았다는 뜻은 아니다.

생성 단계의 직접 밀도 호출은 **3,460,682,865회**, 법선 요청 2,510,442회, 차폐 요청 2,203,698회다. 주 광선 guard의 추가 직접 밀도 호출은 **29,476,628회**이며 표면 조명 요청은 1,194,474회로 승인 수와 같았다. 직접 밀도 계수에는 법선·차폐 함수 내부의 모든 밀도 호출이 포함되지 않는다. 캐시 생성·후보 검사·거부 후 원래 볼륨 계산에 비용이 남으므로 승인 비율만으로 속도 개선을 계산할 수 없다.

## 생성 누계와 메모리·할당

아래 생성 값은 CPU가 기록한 dispatch 누계다. GPU 시간이나 15프레임 스냅샷 합이 아니며, 최초 관측 전 워밍업 및 이전 케이스의 생성이 포함될 수 있다.

| 프리셋 / 항목 | 첫 행 → 마지막 행 | 기록 행 사이 변화 |
|---|---:|---|
| normal-cache / normalFieldBuilds | 3 → 3,300 | 1,099개 간격 모두 +3, 합계 +3,297 |
| surface-hybrid / farSurfaceBuilds | 144 → 1,181 | 1,037개 간격 모두 +1, 합계 +1,037 |
| surface-hybrid / normalFieldBuilds | 3,303 → 3,303 | 변화 0, 이전 케이스 누계 잔류 |

법선 생성 카운터는 cascade 하나마다 증가한다. 코드상 형상·날씨·노이즈 입력 또는 바람 벡터가 달라지면 세 cascade를 갱신한다. 이번 동적 바람 경로의 매 간격 +3은 그 동작과 일치한다. 다만 무효화 사유 문자열이 원자료에 없으므로 바람·날씨 각각의 기여율을 분리 측정했다고 주장하지 않는다. Far Surface는 설계상 매 렌더 재생성되며 모든 관측 상태가 `Rebuilding current-frame surface`다.

| 자원 | normal-cache | surface-hybrid |
|---|---:|---:|
| 주 구름 렌더 타깃 바이트 | 8,355,840 고정 | 8,355,840 고정 |
| 법선 필드 텍스처 바이트 | 786,432 고정 | 0 |
| Far Surface 진단 자원 바이트 | 0 | 8,355,920 고정 |
| 주 렌더 타깃 할당 누계 | 1 고정 | 1 고정 |
| 시간·상층 필드·운해 필드·공간 차폐 자원 | 모두 0 | 모두 0 |

법선 바이트는 32³×3 cascade의 ARGBHalf 텍스처 786,432바이트를 뜻하며 작은 fallback 텍스처·계수 버퍼까지의 전체 할당량은 아니다. Far Surface 바이트는 proxy ARGBFloat 3개 6,266,880바이트, 전체 해상도 RFloat 진단 mask 2,088,960바이트, uint 계수 80바이트를 합한 값이다. 진단 OFF의 메모리와 구분한다.

`targetAllocations`는 주 구름 렌더 타깃의 할당 횟수다. **개별 법선·표면 자원의 allocation count는 이 JSON에 없으므로**, 바이트가 일정한 것만으로 개별 캐시의 재할당이 전혀 없었다고 증명할 수 없다. surface-hybrid의 비활성 법선 메모리·호출은 0이며, 남아 있는 생성 누계를 현재 작업으로 오해하지 않는다.

## 시간 재투영과 기존 캐시의 해석

두 프리셋 모두 시간 재투영은 OFF이고, 시간 상태는 모든 스냅샷에서 `Off`, 13슬롯 계수·시간 자원·reset은 0이다. 이는 **시간 재사용률을 측정하지 않은 것**이며 0% 재사용 결과가 아니다. 시간 재투영이나 타일 압축과 결합한 이득도 이번 실행으로 판정하지 않는다.

| 프리셋 | 1/64 마스크의 상층 몸체 query | 1/64 마스크의 운해 몸체 query | 차폐 캐시 query |
|---|---:|---:|---:|
| normal-cache | 51,584,539 | 122,373,446 | 0 |
| surface-hybrid | 51,646,379 | 117,981,820 | 0 |

상층·운해 query는 모두 exact이며 full/blend는 0이다. 해당 형태 필드가 꺼져 있다는 설정과 일치한다. 공간 차폐 캐시 query=0은 캐시 조회 함수가 비활성이라는 뜻이며, 원래 절차 차폐 계산이 없다는 뜻이 아니다. 스냅샷 수와 카메라 시각이 다르므로 위 합계 차이를 최적화 절감량으로 보고하지 않는다.
