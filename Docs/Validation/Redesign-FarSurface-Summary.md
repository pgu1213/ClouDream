# Far Surface 혼합 렌더링 검증 결과

2026-10-05 · Unity 6000.6.2f1 / Direct3D12

**현재 밀도에서 원경 불투명 표면을 추출하고 실제 렌더링에 사용하는 경로는 동작한다. 그러나 색 오차 예산과 엄격한 fallback 동일성 검사를 통과하지 못해 기본값 OFF를 유지한다.** 별도 픽셀별 수치 오차 허용 검사는 통과했다. 생성·조회·fallback을 포함한 GPU 성능 변화는 이 실행에서 측정하지 않았다.

## 자료와 측정 범위

- 원시 결과: [Redesign-FarSurface.json](Redesign-FarSurface.json). SHA-256: `29b999781cdb179489363ec114b7589d1e27cbad335cd5ff01522ab98d50e526`.
- 검증 구현: [CloudFarSurfaceValidation.cs](../../Assets/LostSkiesClouds/Editor/CloudFarSurfaceValidation.cs).
- 유효한 비교 표본은 **26개**다. 구름 출력 320×192 표본 25개와 resize 검사 160×96 표본 1개로, **FHD 검사나 실제 비행 성능 측정이 아니다.**
- 비교한 출력은 총 1,551,360픽셀이며, 표면 사용 mask가 1인 픽셀은 340,901개, 나머지 fallback 픽셀은 1,210,459개다. 정지·입력 변경·복원 장면이 반복되는 검사이므로 이 합계를 실제 비행의 표면 적용률로 해석하지 않는다.
- 각 비교 직전 temporal 이력을 지우고 첫 프레임의 실제 RGFloat 깊이 모멘트를 읽었다. 장기간 이력 재사용이나 compact dispatch의 비행 성능을 검증한 결과는 아니다. 준비 렌더와 수명 검사용 추가 렌더는 26개 비교 표본 합계에 포함되지 않는다.

노이즈 준비는 기준·후보 렌더러 각각 6회이며, 원본 생성기 실행은 각각 0회다. `noiseLibraryReady=true`이고 기존 `CloudGenerator.asset`의 GPU 출력에서 보존한 RGBAHalf Texture3D 및 mip을 사용했다. [CloudNoise-PreservedValidation.json](CloudNoise-PreservedValidation.json)은 **6개 텍스처, 43개 mip, 45,837,744바이트**의 GPU 읽기, 전체 유한값 검사, 공간·높이 slice별 변화 및 mip별 SHA-256 일치를 기록한다. 원래 텍스처 크기와 mip 구조도 이 자료에서 확인할 수 있다. 이는 보존 노이즈의 동일성 증거이며, 게임 전체 원본 소스 복원이나 구름 기하 높이 범위의 별도 검증을 뜻하지 않는다.

## 제안에서 채택한 원리와 신규 구현

원문 제안의 원리는 **현재 형태에서 추출한 표면으로 먼 거리의 거의 불투명한 구름만 대체하고, 근거리 경계·얇은 구름·관통 구간은 볼륨으로 유지하는 것**이다. 이번 코드는 그 원리를 바탕으로 새로 작성한 화면 광선 기반 proxy다. 보강 자료에서 복원한 원본 구현이나 전체 구름을 대체하는 메시 시스템으로 표현하지 않는다.

[CloudFarSurface.hlsl](../../Assets/LostSkiesClouds/Runtime/CloudFarSurface.hlsl)과 [CloudFarSurface.cs](../../Assets/LostSkiesClouds/Runtime/CloudFarSurface.cs)는 기존 프로필의 높이·지원 범위와 현재 `Density()`를 읽어, 매 렌더마다 구름 출력의 각 축 절반 해상도에서 진입·불투명 도달 거리, 법선, 대표 위치의 차폐량을 생성한다. 기본 근거리 제외 거리는 **12,000m**다. 연속 밀도 표본이 0.002보다 크고, 투과율이 기존 불투명 중단 조건 `T≤0.008`에 도달하며, 진입부터 도달까지 두께가 120–1,600m인 첫 구름 몸체만 후보가 된다.

주 광선에서는 최초 진입과 proxy 진입의 거리·법선 일치, 3×3 이웃의 연속성, 실제 장면 깊이를 검사한다. 기존 진입 이분 탐색과 거리별 표본 간격 및 남은 반복 예산을 따르는 밀도 검사를 다시 수행한다. 여러 얇은 층의 누적 투과율만으로 한 표면을 만드는 것을 막기 위해 중간 빈 구간, 얇은 구간, 근거리·이미 관통한 볼륨을 거부한다. 조건을 만족하지 못하면 기존 볼륨 경로로 돌아간다.

표면 사용 시 현재 팔레트·위상·테두리 빛과 주 광선의 진입 법선을 `CloudIncidentLight()`에 전달하지만, 긴 볼륨의 내부 조명은 **한 대표 차폐 값으로 근사**한다. 현재 프레임 조명 입력을 사용한다는 사실이 정확한 볼륨 재조명을 의미하지 않는다. 이 구현은 밀도 행진을 유지하면서 반복적인 내부 조명 평가를 줄이려는 실험이다.

대표 `far-ocean-success-candidate` 표본에서 proxy 생성 성공은 **15,277/15,360개 광선(99.4596%)**이다. 최종 주 광선의 표면 사용은 **17,351/61,440픽셀(28.2406%)**이고, 같은 표본의 최초 진입 시도 분모도 61,440이다. 나머지 44,089픽셀은 볼륨으로 돌아갔다. 이 표본에서 주된 거부 사유는 이웃·화면 경계 등의 불연속 42,717건, 진입 불일치 1,040건, 유효하지 않은 proxy 332건이다. proxy 생성 성공률을 최종 표면 적용률로 사용하지 않는다.

## 입력 변화와 자원 수명

날씨 입력의 중단·역전 후 복원, 바람 입력 역전 후 복원, 동일 밀도 공간을 유지하는 origin 이동 후 복원은 각각 `weatherRestoredExact`, `windRestoredExact`, `originRestoredExact=true`다. 이는 변경한 후보 입력을 원래 상태로 복원했을 때의 재현성이다. 후보와 기준 볼륨의 엄격한 fallback 동일성 통과를 뜻하지 않는다. 전체 날씨 컨트롤러 전환 검사는 별도다.

안정된 할당, 두 카메라 자원 분리, 명시적 OFF 시 전체 해제, 비호환 옵션으로 전환 시 두 카메라 자원 전체 해제, resize 시 이전 자원 해제, dispose 시 전체 해제 검사가 모두 통과했다. 근거리·내부·얇은 띠·전경 깊이 차단 표본은 모두 표면 사용 0을 확인했다. 가까운 출력의 엄격한 RGB 일치는 별도 표에 기록한 대로 실패한 항목이 있다.

## 비용과 채택 판단의 한계

320×192 진단 표본의 Far Surface 자원은 **983,120바이트**다. 160×96 proxy의 ARGBFloat 텍스처 3개 737,280바이트, 전체 해상도 RFloat 사용 mask 245,760바이트, 20개 uint 카운터 80바이트의 합이다. 이는 해당 진단 모드의 자원 크기이며, 전체 구름 메모리나 FHD 메모리 측정값이 아니다.

대표 표본은 build의 직접 밀도 호출 3,696,013회, 주 광선 guard의 추가 직접 밀도 호출 629,064회, build의 법선 요청 15,360회와 차폐 요청 15,277회를 기록했다. 직접 밀도 호출 계수에는 법선·차폐 함수 내부의 모든 하위 호출이 포함된다고 가정하지 않는다. 표면 후보 준비와 실패한 guard에도 비용이 들며, 원래 볼륨 계산까지 수행하는 fallback에서는 이 작업이 추가될 수 있다.

카운터는 렌더 준비 시 초기화된다. 26개 저장 표본의 최초 진입 시도 합계는 1,348,772건, 표면 승인 340,901건, 시도 후 fallback 1,007,871건이다. 이 fallback 시도 합계는 최초 진입 시도 자체가 없었던 픽셀까지 포함하는 사용 mask의 fallback 1,210,459픽셀과 분모가 다르다. 모두 저장된 진단 렌더의 집계이며 전체 실행 프레임의 계수가 아니다.

`Cloud.FarSurfaceBuild` GPU 마커와 생성·조회·fallback 카운터는 마련했지만 **생성 GPU 시간, 전체 `Cloud.Total`, 실제 비행 속도 변화는 이 GPU 품질 검사 자체에서는 측정하지 않았다.** `builds`는 생성 횟수이며 시간 값이 아니다. 보존 노이즈의 generation=0도 Far Surface 생성 비용이 0이라는 뜻이 아니다. 비동기 GPU 읽기와 진단 계수가 켜진 이 실행을 성능 개선 증거로 사용하지 않는다.

따라서 이번 결과는 **실제 표면 사용, 근거리·얇은 구름·가림 fallback, 제한된 수치 계약과 수명 관리의 구현 검증**이다. 엄격한 출력 동일성과 색 예산 실패를 남긴 채 기본 OFF로 유지한다. 채택 여부를 바꾸려면 표면 사용 부분의 직접 색 통계와 근사 개선을 확인하고, 진단을 끈 동일 조건 Player에서 생성·조회·fallback을 포함한 전체 구름 GPU 시간을 개선 후 다시 비교해야 한다. 현재 구현의 별도 Development 측정에서는 아래처럼 평균 비용이 증가했다.

## 별도 Development Player 성능 측정

[확장 고정 경로](Benchmark-Extensions-Fixed.md)와 [확장 실시간 비행](Benchmark-Extensions-Flight.md)은 진단 GPU readback을 끈 FHD Development Player에서 performance와 surface-hybrid를 각 2회 비교했다. 같은 빌드·품질에서 차이는 useFarSurface 하나다. 고정 경로 Cloud.Total 평균은 **14.541760→19.684317ms(+35.364%)**, aggregate FPS는 **63.491969→47.826620**이다. 단, surface-hybrid 반복 평균이 **23.994370→15.374264ms**로 크게 달랐고 범위/평균은 **43.79%**다. 따라서 합산 변화율은 안정된 재현 효과로 주장하지 않는다. 실제 시간 36초 비행에서는 **14.619505→19.323824ms(+32.178%)**, FPS는 **40.715856→34.122222**이며 surface 반복 Cloud 편차는 9.14%다.

Cloud.FarSurfaceBuild의 관측 마커 프레임 평균은 고정 경로 **2.116173ms(1,080표본)**, 비행 **1.788386ms(2,458표본)**다. 두 경우 이 마커 표본 수는 해당 프리셋의 기록 프레임 수와 같지만 하위 마커는 Cloud.Total에 이미 포함되므로 더하지 않는다. 실제 FHD performance 출력 크기에서 표면 자원은 **6,266,964바이트**였다. 모든 Cloud.Total 표본을 확보했고 고정 경로 포즈는 일치했다. 비행은 동일 시간 함수지만 FPS별 포즈 표본은 다르다. 현재 품질 예산 실패와 평균 비용 증가를 함께 고려해 기본 OFF를 유지한다.
